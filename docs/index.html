Pacer / Developer handoff

Get Pacer onto
private TestFlight.

For the Apple Developer account owner: sign the iPhone app, upload a build, and invite one friend. No App Store release required.

Open the Pacer repository ↗

Public code, private distribution. The repository and this guide are public. TestFlight access can remain invitation-only: use an email invitation and leave public tester links disabled. Do not share your Apple password.

Have these ready

  • A Mac with Xcode 16 or later and an active paid Apple Developer Program membership.
  • Access to your Apple Developer account and App Store Connect. Accept any outstanding agreements first.
  • Your friend's email address. They need an iPhone running iOS 17 or later and Apple's TestFlight app.
  • The app icon is already included and configured; no icon setup is needed.

The account owner's steps

  1. Download and open the app project

    On github.com/batemapf/pacer, choose Code → Download ZIP and unzip it, or clone the repository. Use the latest main branch.

    Open Pacer.xcodeproj in Xcode. Opening the folder or Package.swift selects the standalone pace-engine package, which runs tests rather than launching the app.

  2. Choose your paid signing team

    In Xcode → Settings → Accounts, add your Apple Account. Select the blue Pacer project in the sidebar, then the Pacer target → Signing & Capabilities.

    Enable Automatically manage signing and select your paid developer team. Choose a unique bundle identifier, such as com.yourteam.pacer. The current identifier is com.batemapf.pacer; change it if it is unavailable to your team.

    Xcode can register the app ID and generate signing assets automatically. If registration is blocked, register an explicit app ID with the identical bundle identifier in Certificates, Identifiers & Profiles, then retry signing. Keep the project's background location and audio modes.

  3. Confirm the included app icon

    Pacer includes an opaque 1024 × 1024 icon in Pacer/Assets.xcassets/AppIcon.appiconset, configured for Debug and Release. No catalog or image setup is needed.

    To check it in Xcode, open Assets → AppIcon and confirm the target's General → App Icons and Launch Screen uses AppIcon.

  4. Create the App Store Connect app record

    Open App Store Connect, then My Apps → + → New App. Choose iOS, an available app name, and a primary language.

    Select the same bundle identifier used in Xcode. Enter any unique internal SKU, such as pacer-private-001, and create the record.

    Creating this record does not publish the app or create a public App Store listing.

  5. Archive and upload

    In Xcode's toolbar, select the Pacer scheme and Any iOS Device (the generic device destination, not a simulator). Choose Product → Archive.

    In Organizer, select the archive and choose Distribute App → App Store Connect → Upload. Follow the signing and validation prompts and upload.

    Fix any icon or signing errors reported during validation. The repository's successful simulator build verifies compilation, but does not verify distribution signing or upload readiness.

  6. Complete the TestFlight build information

    After Apple finishes processing the upload, open the app's TestFlight tab. Complete any missing export-compliance information according to the actual build. Pacer does not implement its own encryption.

    Add the beta description, feedback email, and your beta review contact details. No app login or demo credentials are required. Include these review notes:

    Pacer is an outdoor jogging pace coach. Tap Start run and allow Precise Location. Coaching needs reliable outdoor GPS readings for at least 10 seconds. Set a target pace and enable Spoken coaching to hear speed-up or slow-down prompts. Target pace and miles/km can be changed during a run. There is no account or sign-in.

  7. Invite your friend as an external tester

    Under TestFlight → External Testing, create a group such as Private Pacer, add the uploaded build, and submit it for TestFlight Beta App Review. The first external build normally requires review.

    Add your friend's email to the group. Once the build is approved, enable testing and send the invitation if it has not already been sent. Leave Public Link disabled.

    Your friend does not need an App Store Connect role or access to your developer account. Use external testing rather than granting account privileges solely to install the app.

  8. Install and test on the iPhone

    Your friend opens the email invitation on their iPhone, accepts it in TestFlight, and taps Install.

    Allow Precise Location, play music, and start an outdoor run. Check both coaching directions, changes to the target pace, the miles/km toggle, and several minutes with the screen locked. Confirm that music lowers during a prompt and returns afterward.

Keeping it available

Each TestFlight build expires 90 days after upload. Before expiry, pull the latest code and upload a replacement build.

In this project, the build number is stored directly in Pacer/Info.plist: increment Bundle version (CFBundleVersion), currently 1, for each upload. Changing only the target's Build setting will not update that literal plist value.

Add the replacement build to the same external group and complete any requested review. Keep the developer membership active. Do not submit an App Store version for release unless you later decide you want public distribution.

If something gets stuck

  • Only tests run: open Pacer.xcodeproj and select the Pacer app scheme.
  • Archive is unavailable: select the generic iOS device destination rather than a simulator.
  • Bundle ID or signing error: confirm the paid team and matching unique identifier in Xcode and App Store Connect.
  • Missing app icon: check asset-catalog target membership and the target's App Icon source.
  • Friend cannot install: confirm external beta approval, group/build assignment, invitation acceptance, and an unexpired build.

Apple may change menu wording. See Apple's TestFlight overview for current distribution requirements.
